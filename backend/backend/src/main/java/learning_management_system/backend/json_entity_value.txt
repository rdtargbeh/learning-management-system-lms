Each permission consists of:

Action: CREATE, READ, UPDATE, DELETE
Resource: COURSE, USER, ASSIGNMENT, EXAM, etc.
Scope: SYSTEM, TENANT, RESOURCE
Conditions (Optional): Restrict when permissions apply.


Role	Permissions (Example)
GLOBAL	Full control over all system configurations.
TENANT	Manages a single institution (e.g., a university).
SYSTEM	Predefined system-level permissions (read-only).
USERS	General users with minimal read access.
INSTRUCTOR	Can create, update, and grade courses & exams.
ADMIN	Can manage users, roles, and global settings.
STUDENT	Can view courses, take exams, and submit assignments.
SUPPORT_STAFF	Can assist with student/teacher issues, but no teaching rights.

Global Admin (GLOBAL)
Resource: SYSTEM
Permissions:
MANAGE_USERS → Full access to all users.
CONFIGURE_SYSTEM → Can update system settings.
MANAGE_TENANTS → Can create/delete institutions.

Tenant Admin (TENANT)
Resource: TENANT, USER, COURSE
Permissions:
CREATE_COURSE → Can create/edit courses.
ASSIGN_TEACHERS → Can assign instructors.
MANAGE_TENANT_SETTINGS → Can update tenant settings.

System Role (SYSTEM)
Read-only role with no direct creation rights.
Permissions:
VIEW_SYSTEM_SETTINGS
VIEW_USER_STATS

 Users (USERS)
Limited read access (basic navigation).
Permissions:
VIEW_PUBLIC_COURSES
ENROLL_COURSES

 Instructor (INSTRUCTOR)
Manages courses & exams.
Permissions:
CREATE_ASSIGNMENTS
GRADE_EXAMS
MANAGE_COURSE_CONTENT

Admin (ADMIN)
Manages users & reports.
Permissions:
MANAGE_USERS
VIEW_REPORTS
DELETE_STUDENT_ACCOUNTS

Student (STUDENT)
Participates in courses.
Permissions:
SUBMIT_ASSIGNMENTS
TAKE_QUIZZES
VIEW_COURSE_CONTENT

Support Staff (SUPPORT_STAFF)
Assist users but no teaching rights.
Permissions:
VIEW_STUDENT_GRADES
